# Methodology

Open Work Relay is built from a few plain beliefs.

## 1. The Human Should Not Be The Hallway

When one AI finishes and another AI needs to continue, the user should not have to copy the source, rewrite the limits, explain the decision, and audit the result by hand.

The handoff should be visible.

## 2. State Belongs Somewhere Inspectable

Private chat history is a bad system of record.

The task record can live in:

- a Markdown file,
- a GitHub issue,
- a Trello card,
- a Linear issue,
- a Notion page,
- another queue the agent can actually read and write.

The important part is not the brand of queue. The important part is that work has a shared place to land.

## 3. A Task Is Not A Prompt

A prompt asks for an answer.

A task asks for a result, with source and limits attached.

That means every task needs the seven-part record:

1. Outcome
2. Owner / next actor
3. Source material
4. Context / decisions so far
5. Allowed actions
6. Stop rules / human gates
7. Done evidence / receipt

## 4. Receipts Beat Vibes

Do not ask the agent whether it is done.

Make the agent leave evidence.

A receipt should say what changed, what sources were used, what was touched, what remains, and who should act next.

## 5. Open Means The Core Is Not Gated

This kit is donation-supported, not paywalled.

People should be able to copy the protocol, teach it, adapt it, and run it without buying access to the real version.

Support is welcome. Access is not conditional.

## 6. Small First, Then Automate

Start with the manual queue.

Run the smoke test.

Only add scripts, MCP tools, or automations after the loop is clear enough to verify.
