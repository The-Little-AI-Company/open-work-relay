# Source Grounding

Agent Relay is built from public problem framing and independent implementation choices.

No paid guide or private packet was used.

## Public Sources Used

- Public Substack preview: `https://natesnewsletter.substack.com/p/ai-agent-handoffs`
- Public YouTube video: `https://www.youtube.com/watch?v=QSK4vf_ZTRA`
- User-provided autogenerated transcript of the YouTube video

## Transcript-Grounded Concepts

The core method follows concepts described in the public video transcript:

- multiple AI tools do different parts of the work,
- the human becomes the handoff layer between tools,
- a shared queue can be read by people and agents,
- a task should include outcome, source/context, owner, allowed work, stop point, and evidence,
- agents can claim work,
- agents can move work through statuses,
- agents should move ambiguous work to `needs-input`,
- receipts show what happened,
- work should be able to leave a private chat.

## Transcript-Grounded Example Workflows

### Client Call / Follow-Up

The client-call example comes from the transcript's prompt-mode versus work-mode contrast:

```text
Transcript -> Decision -> Promise Boundary -> Draft Follow-Up -> Flag Judgment -> Stop Before Send
```

Agent Relay turns that into:

- attach the call transcript,
- state the decision that was made,
- state what should not be overstated,
- draft the follow-up,
- flag what needs human judgment,
- stop before sending,
- leave a receipt.

### Support

The support example comes from the transcript's support-ticket work-mode pattern:

```text
Classify -> Attach History -> Check Known Issue -> Escalate -> Product Task -> Show Stop
```

Agent Relay turns that into:

- classify the ticket,
- attach customer or conversation history,
- check known issue or prior pattern,
- create a product task only when an escalation rule is met,
- show where the agent stopped and why.

### Schedule / Pickup Change

The schedule example comes from the transcript's pickup-time pattern:

```text
Change -> Check -> Draft -> Pause
```

Agent Relay turns that into:

- identify the new constraint,
- check what the changed time affects,
- draft the messages or notes,
- pause for human approval before anything is sent, booked, canceled, or decided.
